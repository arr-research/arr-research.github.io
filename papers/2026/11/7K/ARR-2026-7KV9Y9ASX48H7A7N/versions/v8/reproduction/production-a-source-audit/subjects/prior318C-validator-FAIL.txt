4. ZIP and manifest scope, plus required caller filesystem safety

The transport ZIP hash/length is compared to a single execution-log announcement for the exact production-b archive/status.
This is not a generic secure-extractor certificate. validate never extracts. There are further known limitations that the caller must respect:
(a)fresh compares string spellings, not normalized Windows destination identities. Two absent paths differing only by case can pass the repeated-destination check. It also accepts an empty destination list, relative paths, and ancestor/descendant destinations. This does not overwrite anything inside this read-only function, but is not proof that the supplied output set is the complete disjoint destination set.
(b)fresh checks is_symlink on ancestors, not Windows junctions/reparse points. Existing ancestor junctions can redirect a newly created child. Python's primary pathlib documentation distinguishes is_junction from is_symlink. Before any mutation, parent must verify the exact intended absolute destinations, trusted physical parents and no junction/reparse traversal, and exclude concurrent path replacement. Exclusive creation of ordinary files alone does not establish containment through a junction parent.
(c)safe_names omits the superscript-digit COM/LPT reserved names listed by Microsoft. This is a real generic helper limitation. For this exact candidate's complete validation, the source-capture path universe is pinned by the1045-row trusted Git manifest (no non-ASCII path appeared in the metadata inspection), while other accepted names are fixed ASCII patterns. An arbitrary new COM-superscript member is consequently rejected by the exact universe unless the caller substitutes an untrusted source manifest. Do not promote this helper to a generic Windows-name validator.
(d)line96 rejects directory entries identified by is_dir and UNIX symlink mode, but does not positively require UNIX regular-file mode: FIFO/device/other mode metadata is not excluded by that expression. The parent assignment explicitly promises ordinary-file extraction. It must ignore archive permissions/type instructions and exclusively write ordinary file contents, never recreate special nodes. The error label 'Archive regular files' is broader than this single predicate; no such metadata proof is asserted in the returned scope.
(e)the declared uncompressed limit is useful, but the ZIP is read for its hash before those limits and no separate compressed-file size ceiling exists. This is a controlled, bound production return, not protection against arbitrary unbounded hostile input. Raw inputs must be immutable through validation and subsequent extraction; otherwise the later reads can refer to different bytes. Caller must bind the exact validated ZIP bytes again at extraction/delivery.
These are concrete caller obligations/limitations, separated from the strict sentinel blocker C1. Because the function makes no writes and the assignment already reserves exclusive ordinary-file extraction to the parent, this review does not invent an observed filesystem escape or demand that validate itself become an extractor.
